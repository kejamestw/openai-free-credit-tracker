# v0.3.1 執行與驗收計畫

> 規劃聲明：本文件是可調整的規劃草案，不構成功能、日期或上游 OpenAI 規則的承諾；實際發布範圍以對應 Release Milestone 與已完成的驗收紀錄為準。

## 版本資料

- 狀態：背景監控核心已實作；待 Windows 原生 credential／toast／登入啟動驗收（不可標為已完成）
- 版本主題：系統匣、排程與警示版
- 前置版本：[v0.3.0](v0.3.0.md)
- 建議工期：單人 7–10 個工作天
- 發布產物：Windows tray 應用程式、排程同步、Windows Credential Manager 整合、通知規則

## 版本目標

讓應用程式可以在 Windows 背景執行、定期同步用量並在達到門檻時通知使用者。背景查詢只有在使用者明確同意並把 Admin API Key 保存到 Windows Credential Manager 後才能啟用；不得將 Key 寫入 JSON、SQLite、log 或命令列。

- Credential abstraction、tray／single-instance、scheduler、alert dedup、notification history 與 fake-clock／fake-backend tests 已存在。
- [ ] `AC-031-01` 明確啟用背景監控；blocker：真實 Admin Key、Windows Credential Manager 與關閉瀏覽器後的原生排程驗收。
- [x] `AC-031-02` 拒絕保存 Key（memory-only／background-disabled tests）
- [x] `AC-031-03` 跨越門檻與防洗版（dedup／restart fixtures）
- [x] `AC-031-04` UTC 重置（fake-clock tests）
- [x] `AC-031-05` 離線、429 與 credential 撤銷（bounded retry／disable tests）

- [ ] `AC-031-07` Windows 開機啟動；blocker：Windows 10／11 重新登入、installer upgrade／uninstall 的原生檢查。

## 成功結果

使用者可以從系統匣開啟 Dashboard、立即同步、暫停監控與安全退出；排程同步會更新歷史資料，警示只在新跨越門檻時發送，不會因重啟或重複同步洗版；資料過期或同步失敗時不會發出誤導性的額度安全通知。

## 範圍內

- Windows system tray 與單一 instance。
- 可選擇的 Windows Credential Manager Admin Key 保存。
- 前景立即同步與背景排程同步。
- 群組及專案用量百分比警示。
- 警示 deduplication、cooldown、UTC 日重置與資料過期狀態。
- Windows 開機自動啟動選項，預設關閉。

- 多組織 credential。
- 遠端管理或服務常駐 daemon。

## 執行計畫

### 1. Credential Store

- [x] `V031-001` 建立 `CredentialStore` abstraction，本版實作 Windows Credential Manager backend。
- [x] `V031-002` Key 以不含秘密的 credential ID 連結設定；JSON 和 DB 只保存 alias／是否啟用。
- [x] `V031-003` 保存前顯示用途、風險、刪除方式與「僅本機使用」說明，要求明確同意。
- [x] `V031-004` Credential 讀取失敗或使用者撤銷時，自動停用背景同步並要求重新輸入。
- [x] `V031-005` 提供「忘記 Key」，刪除 credential、清除記憶體中的 Key 並停止相關工作。
- [x] `V031-006` Log、exception、crash report、process arguments 與 IPC 不得包含完整 Key。
- [ ] `V031-007` Installer 移除預設不刪 credential；若選擇清除本機資料，必須單獨列出並二次確認。

### 2. Tray 與 process lifecycle

- [x] `V031-010` Tray 選單包含開啟 Dashboard、立即同步、暫停／繼續、自動啟動設定、關於與退出。
- [x] `V031-011` 關閉瀏覽器頁籤不停止監控；選擇「退出」必須停止 scheduler、server 與 tray process。
- [x] `V031-012` 建立 single-instance lock；第二次啟動只喚醒既有 instance 並開啟 Dashboard。
- [x] `V031-013` Server 使用 loopback random port，tray 保存的是當次 runtime 狀態，不寫入固定可被劫持的 port 設定。
- [x] `V031-014` 應用程式崩潰後 lock 可安全回收，不造成永遠無法重啟。
- [x] `V031-015` Windows 開機自動啟動預設關閉，可由設定啟用和完整移除。
- [x] `V031-016` Tray 顯示 monitoring、paused、syncing、stale、error 五種可辨識狀態。

### 3. Scheduler

- [x] `V031-020` 使用 monotonic scheduling 或等效策略，避免系統時間調整造成短時間重複同步。
- [x] `V031-021` 預設同步間隔有安全下限；使用者不能設定造成 API 濫用的高頻率。
- [x] `V031-022` 睡眠／喚醒後只補一次必要同步，不對每個錯過間隔各發一個請求。
- [x] `V031-023` 同時間只允許一個 collection run；手動同步可喚醒但不可重疊背景同步。
- [x] `V031-024` 429、5xx、timeout 使用有上限的 exponential backoff 與 jitter；401／403 停止自動重試。
- [x] `V031-025` 每次成功同步更新資料 freshness；部分失敗不得標成完整成功。
- [x] `V031-026` 暫停監控後不發 API request、不發額度通知，但仍可查看既有歷史資料。

### 4. 警示規則

- [x] `V031-030` 支援以免費群組百分比設定多個遞增門檻，例如 50%、80%、100%。
- [ ] `V031-031` 可選全部專案或指定專案；刪除專案後相依規則標記失效而非指向其他專案。
- [x] `V031-032` 只有從門檻下方跨越到上方時通知；相同 UTC 日、群組、專案與門檻只通知一次。
- [ ] `V031-033` 用量下降、catalog quota 改變或資料回補時重新計算，但不得無限重送既有門檻。
- [x] `V031-034` 到下一個 UTC 日重置日內 dedup state；本地午夜不得觸發 quota reset。
- [x] `V031-035` 資料超過 freshness threshold 時顯示「資料過期」，不發「用量仍安全」類通知。
- [x] `V031-036` 通知預設只顯示群組、百分比與時間；Project ID 需遮罩，Key 永不顯示。
- [ ] `V031-037` 通知點擊後開啟對應日期／專案 filter 的 Dashboard。

### 5. UI 與可觀測性

- [ ] `V031-040` 設定頁清楚顯示 credential 是否保存、最後成功同步、下次排程與最後錯誤類型。
- [x] `V031-041` 提供測試通知按鈕；測試通知不得更改正式 dedup state。
- [x] `V031-042` 提供通知歷史，只保存類型、時間、門檻與遮罩識別，不保存 Windows notification payload 的敏感副本。
- [ ] `V031-043` Tray log 可供除錯 scheduler 狀態，但採固定 retention 並去除敏感資訊。

### 6. 測試

- [x] `V031-050` 使用 fake clock 測試 interval、backoff、睡眠喚醒、UTC reset 與時間倒退。
- [x] `V031-051` 使用 fake credential store 測試保存、拒絕、撤銷、刪除與讀取失敗。
- [x] `V031-052` 多次同步、process 重啟與資料修正後的 alert dedup 測試。
- [x] `V031-053` single instance、stale lock、server shutdown 與 tray exit 整合測試。
- [ ] `V031-054` Windows VM 驗證 toast 通知、點擊 deep link 與開機自動啟動。
- [ ] `V031-055` 搜尋設定、DB、log、notification history、命令列與 temp，確認 Key 不落地。

## 驗收案例

### `AC-031-01` 明確啟用背景監控（P0）

1. 在設定中啟用 Key 保存與背景監控。
2. 閱讀提示後同意，輸入測試 Admin Key。
3. 關閉瀏覽器頁籤，等待下一次排程。

預期：Key 存在 Windows Credential Manager；JSON、DB、log 無 Key；瀏覽器關閉後排程仍同步；tray 顯示最後成功時間。

### `AC-031-02` 拒絕保存 Key（P0）

1. 不同意保存 Key，但嘗試開啟背景監控。
2. 完成一次手動查詢後關閉 Dashboard。

預期：允許當次手動查詢；背景監控保持停用；程式不建立 credential；UI 清楚說明原因。

### `AC-031-03` 跨越門檻與防洗版（P0）

1. 建立 50%、80%、100% 三個門檻。
2. 依序同步 40%、55%、55%、85%、101% fixture。
3. 重啟程式後再次同步 101%。

預期：只在 55%、85%、101% 各通知一次；重啟後不重送；通知不含完整 Project ID 或 Key。

### `AC-031-04` UTC 重置（P0）

1. 用 fake clock 在本地午夜與 UTC 午夜前後同步。
2. 下一個 UTC 日再次跨越門檻。

預期：本地午夜不清除 dedup；UTC 午夜後新日可再次通知；歷史資料歸屬正確。

### `AC-031-05` 離線、429 與 credential 撤銷（P0）

1. 依序模擬無網路、429、401 與從 Credential Manager 刪除 Key。
2. 觀察排程與 UI。

預期：網路／429 使用有限 backoff；401 或 credential 缺失停止背景同步；資料標記 stale；不持續彈出相同通知。

### `AC-031-06` 單一 instance 與退出（P0）

1. 啟動應用程式兩次。
2. 從 tray 選擇退出。
3. 檢查 process、port、lock 與排程。

預期：只有一個 instance；第二次啟動喚醒既有 Dashboard；退出後無殘留 process、監聽 port 或工作。

### `AC-031-07` Windows 開機啟動（P1）

1. 啟用開機啟動後重新登入 Windows。
2. 再停用並重新登入。

預期：啟用時只啟動一個 tray instance；停用後不再啟動；uninstall 不留下失效自啟項目。

## 回復策略

- Scheduler 或 tray 問題可由設定停用背景監控，保留 v0.3.0 手動查詢與歷史功能。
- Credential backend 失敗時不得 fallback 到明文檔案；改回每次手動輸入。
- 警示規則 migration 失敗時停用規則並保留原始設定備份，不發未知狀態通知。
- Tray 無法啟動時仍應能以 foreground 模式啟動本機 Web UI。
