# v0.2.0 執行與驗收計畫

> 規劃聲明：本文件是可調整的規劃草案，不構成功能、日期或上游 OpenAI 規則的承諾；實際發布範圍以對應 Release Milestone 與已完成的驗收紀錄為準。

## 版本資料

- 狀態：未開始
- 版本主題：Windows 可設定與可分發版
- 前置版本：[v0.1.0](v0.1.0.md)
- 建議工期：單人 8–12 個工作天
- 發布產物：Windows portable EXE、Windows installer、設定格式說明、模型目錄 schema

## 版本目標

建立可長期演進的 Windows 應用程式基礎：版本化設定檔、固定的應用程式資料路徑、可驗證的 JSON 模型目錄、可重複建置的 EXE 與 installer。使用者設定在升級後必須保留，但 Admin API Key 不得以明文寫入設定檔。

## 成功結果

使用者可以透過 UI 或設定檔調整非敏感選項，重新啟動或升級程式後設定仍存在；損壞或不相容的設定不會讓程式無法啟動；模型目錄有明確 schema、來源與生效日期；Release 產物能在乾淨 Windows 環境安裝與移除。

## 設定契約 v1

建議設定檔只保存非敏感資料：

```json
{
  "schema_version": 1,
  "ui": {
    "language": "zh-TW",
    "open_browser_on_start": true
  },
  "network": {
    "request_timeout_seconds": 45
  },
  "updates": {
    "channel": "stable",
    "check_on_start": true
  }
}
```

明確禁止的欄位：Admin API Key、Authorization header、原始 API response、Organization 或 Project 的私人顯示名稱。

## 執行計畫

### 1. 設定服務與路徑

- [ ] `V020-001` 建立集中式 path service，禁止各模組自行拼接使用者目錄。
- [ ] `V020-002` 定義 config、data、cache、log 路徑，portable 模式不得意外寫入安裝目錄。
- [ ] `V020-003` 建立設定 schema v1、型別驗證、預設值與未知欄位政策。
- [ ] `V020-004` 實作 atomic write：先寫暫存檔、flush 後替換，避免中途關閉造成半份 JSON。
- [ ] `V020-005` 每次覆寫前保留一份最近可用備份；損壞時回復預設值並提示使用者。
- [ ] `V020-006` 設定讀寫失敗不得阻止 UI 啟動；畫面需提供設定檔位置與修復方法。
- [ ] `V020-007` 提供設定匯出時再次掃描敏感欄位，禁止 Key 混入。

### 2. 設定 UI

- [ ] `V020-010` 提供開機時開啟瀏覽器、request timeout、更新通道與啟動檢查更新等選項。
- [ ] `V020-011` UI 儲存前驗證範圍，例如 timeout 不得小於 5 秒或大於 300 秒。
- [ ] `V020-012` 提供「恢復預設值」，執行前顯示會受影響的欄位。
- [ ] `V020-013` 顯示目前設定 schema 與程式版本，方便支援與除錯。
- [ ] `V020-014` 設定變更若需要重啟，必須明確標記且不能假裝已套用。

### 3. 模型目錄 schema

- [ ] `V020-020` 正式定義 `schema_version`、`catalog_version`、`effective_from`、`last_verified` 與來源欄位。
- [ ] `V020-021` 將價格、免費資格、群組額度的來源分別記錄，不以模型價格頁替代額度規則來源。
- [ ] `V020-022` 為模型加入 `enabled` 或有效期限語意，不直接刪除仍可能出現在歷史回應中的模型。
- [ ] `V020-023` validator 檢查重複 ID／alias、負價格、缺少來源、未知群組與不支援 schema。
- [ ] `V020-024` 目錄無法載入時使用內建最後可用版本，並在 UI 顯示警告。
- [ ] `V020-025` 未知模型必須顯示為「目錄未識別」，不得讓使用者誤認為已確認免費或已確認計價。
- [ ] `V020-026` 文件化目錄更新 PR 流程、官方來源要求與審查清單。

### 4. 手動版本檢查

- [ ] `V020-030` 定義唯讀 update manifest，至少包含版本、發布日期、Release URL 與最低支援版本。
- [ ] `V020-031` 程式只在使用者啟用時檢查；網路失敗不影響 Usage 查詢與啟動。
- [ ] `V020-032` 正確比較 stable、pre-release 與目前版本，不以字串大小直接比較 SemVer。
- [ ] `V020-033` 顯示 Release notes 連結，但本版不得自動下載或執行任何檔案。

### 5. Windows 發行

- [ ] `V020-040` Portable EXE 與 installer 使用同一份可重複建置輸入。
- [ ] `V020-041` Installer 支援一般使用者權限安裝，不要求不必要的系統管理員權限。
- [ ] `V020-042` 安裝、升級與移除不得刪除使用者設定；提供明確的「連同資料移除」選項時必須二次確認。
- [ ] `V020-043` EXE、installer、manifest 與 checksum 一起發布。
- [ ] `V020-044` CI 建立 Windows 安裝／移除 smoke test，並檢查 Start Menu shortcut 與版本資訊。
- [ ] `V020-045` 文件列出 Windows 支援版本、portable 與 installer 差異、資料位置和備份方法。

### 6. 測試

- [ ] `V020-050` 設定預設值、round trip、未知欄位、錯誤型別、損壞 JSON 與無寫入權限測試。
- [ ] `V020-051` schema 遷移測試使用 golden files，測試後不得改動輸入 fixture。
- [ ] `V020-052` 模型目錄 validator 的每一個失敗規則都有獨立 fixture。
- [ ] `V020-053` 打包後執行資源載入與設定路徑整合測試。
- [ ] `V020-054` Installer 進行 install → launch → upgrade → uninstall 流程測試。

## 自動化驗證

```powershell
python scripts\validate_models.py
python -m pytest -q
node --check web\js\app.js
scripts\build_windows.bat
```

另由 Windows CI 執行 installer smoke test。預期所有命令 exit code 為 0，且測試過程未在 repository 根目錄產生 config、data 或 log。

## 驗收案例

### `AC-020-01` 首次建立設定（P0）

1. 在全新的 Windows 使用者帳號啟動程式。
2. 開啟設定頁，修改瀏覽器啟動與 timeout。
3. 儲存並重新啟動。

預期：設定寫入文件所述 config 路徑；重啟後值保持；JSON 具有 `schema_version: 1`；檔案中沒有 Key。

### `AC-020-02` 損壞設定復原（P0）

1. 關閉程式後，將設定檔改成不完整 JSON。
2. 重新啟動程式。

預期：UI 仍可開啟；使用安全預設值；顯示修復訊息與檔案位置；損壞檔案被保留供診斷，但不包含新寫入的敏感資訊。

### `AC-020-03` 設定 atomic write（P0）

1. 在儲存設定時模擬 process 終止或磁碟寫入失敗。
2. 重新啟動。

預期：舊設定或完整新設定至少一份可讀，不出現半份 JSON；程式可啟動。

### `AC-020-04` 模型目錄驗證（P0）

1. 依序注入重複 alias、負價格、缺少來源、不支援 schema 的 fixture。
2. 執行 validator 並啟動應用程式。

預期：validator 非零結束並指出精確欄位；應用程式拒絕錯誤目錄並使用最後可用內建目錄。

### `AC-020-05` 未知模型顯示（P0）

1. 使用包含未知模型的匿名 Usage fixture。
2. 查詢並檢查 UI 與匯總值。

預期：未知模型不計入已確認免費額度；畫面顯示模型名稱、token 數和「未識別」狀態。

### `AC-020-06` 安裝與升級（P0）

1. 在乾淨 Windows VM 安裝 v0.2.0 候選版。
2. 儲存非敏感設定。
3. 使用較新的候選 build 覆蓋升級並啟動。
4. 移除應用程式。

預期：安裝與升級成功；設定保留；移除程式不會未經確認刪除使用者資料；沒有殘留執行中 process。

### `AC-020-07` 手動版本檢查（P1）

1. 測試較新 stable、只有 pre-release、相同版本、manifest timeout 四種情況。
2. 在 stable 與 beta channel 分別檢查。

預期：版本比較正確；timeout 不影響其他功能；程式不下載或執行更新檔。

## 回復策略

- 安裝升級失敗時允許使用者重新安裝舊版本，設定 schema v1 必須仍可讀。
- 寫入設定前保留最近可用備份；自動復原不得覆寫原始損壞檔。
- 模型目錄更新失敗時回到程式內建 catalog，不影響程式啟動。
- Installer 不得在 rollback 時刪除使用者 config 或 data。
