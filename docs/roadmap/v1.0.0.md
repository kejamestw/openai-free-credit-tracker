# v1.0.0 執行與驗收計畫

> 規劃聲明：本文件是可調整的規劃草案，不構成功能、日期或上游 OpenAI 規則的承諾；實際發布範圍以對應 Release Milestone 與已完成的驗收紀錄為準。

## 版本資料

- 狀態：未開始
- 版本主題：穩定契約與正式產品版
- 前置版本：[v0.5.0](v0.5.0.md)
- 建議工期：單人 15–25 個工作天，不含外部安全審查等待時間
- 發布產物：三平台正式安裝包、穩定契約文件、完整使用與維護文件、安全審查報告

## 版本目標

將專案從功能完整的 pre-1.0 工具提升為具有明確相容性承諾、可升級資料格式、完整文件、安全發布流程與跨平台安裝體驗的正式產品。v1.0.0 不以新增大型功能為主，而是凍結並驗證已存在的契約。

## 成功結果

使用者可以從受支援的舊版本升級而不遺失設定、credential references、歷史或警示；外部整合可依文件使用版本化 App API 與 export schema；三平台 artifact 有可驗證來源；安全審查沒有未處理的 critical/high finding；安裝、操作、備份、升級、復原與移除都有完整文件。

## 進入條件

- [ ] [v0.5.0](v0.5.0.md) 所有發布門檻已通過，且至少有一段實際使用觀察期。
- [ ] 所有候選穩定契約已完成 inventory，沒有仍未決定的欄位或語意。
- [ ] 已選定 v1.0 支援 OS／架構、資料保留與舊版本升級範圍。
- [ ] 已安排獨立安全審查者，且有 finding 處理與例外核准流程。
- [ ] 已建立 release candidate channel 與至少兩輪 RC 的時間。

## v1 穩定契約範圍

本版承諾穩定的是應用程式自己的介面，不承諾外部 OpenAI 模型、價格、免費資格或上游 API 永不改變：

- App HTTP API `/api/v1` 的 endpoint、必要欄位、error code 與相容性政策。
- 設定 schema 與 migration／預設值政策。
- SQLite schema migration 與 backup／restore 行為。
- CSV／JSON export schema 與版本欄位。
- 模型目錄 schema、來源與不支援版本處理。
- Profile／credential reference 的本機契約。
- CLI／啟動參數中被文件列為 public 的部分。
- Release manifest、更新通道與 artifact 驗證政策。

## 範圍內

- Public contract inventory、版本化、文件化與 compatibility tests。
- 從支援舊版本升級至 v1.0.0 的 migration matrix。
- 完整安全審查、威脅模型與 finding 修復。
- 長時間穩定性、錯誤復原、效能與跨平台 regression tests。
- 中英文使用者、管理、架構、API、資料格式、備份與 troubleshooting 文件。
- 三平台正式簽署／驗證的 installer 與更新流程。
- RC、rollback、support window 與 deprecation policy。

## 範圍外

- 新增重大產品功能或重寫 UI framework。
- 承諾上游 OpenAI API、模型、價格或免費活動規則穩定。
- 雲端帳號、遠端同步、團隊協作與 mobile app。
- 未經 migration 的破壞性 schema 重置。
- 為達到日期而降低安全或資料相容性門檻。

## 執行計畫

### 1. 契約盤點與凍結

- [ ] `V100-001` 列出所有 HTTP endpoints，標記 public、internal、deprecated；public endpoint 移至 `/api/v1`。
- [ ] `V100-002` 為每個 public endpoint 定義 request、response、error envelope、時間格式、nullable 與未知欄位政策。
- [ ] `V100-003` 定義設定 schema compatibility：v1.x 可新增 optional 欄位，不移除或改變既有欄位語意。
- [ ] `V100-004` 定義 DB migration 保證、backup 時機、forward-only 規則與舊版無法開啟新 DB 的錯誤行為。
- [ ] `V100-005` 凍結 CSV／JSON export schema v1；新增欄位或格式變更必須透過 schema version。
- [ ] `V100-006` 凍結模型目錄 schema v1，明確區分 catalog content 更新與 schema 更新。
- [ ] `V100-007` 定義 SemVer、deprecation、最低通知期、support window 與 end-of-support 文件。
- [ ] `V100-008` 為所有契約建立 golden／consumer compatibility tests。

### 2. 上游 API 隔離

- [ ] `V100-010` OpenAI Admin API 只透過 adapter/client 進入 domain，不讓原始 response shape 滲透 UI／DB。
- [ ] `V100-011` Parser 容忍未知 optional 欄位、欄位順序與 opaque ID 格式變動。
- [ ] `V100-012` 必要欄位缺失或型別不符時回傳穩定 app error code，不直接顯示 Python exception。
- [ ] `V100-013` Usage 與 Costs 不一致時分別呈現來源、資料時間與完整性，不把估算標示為帳單事實。
- [ ] `V100-014` 模型、價格、資格與額度規則可透過已驗證 catalog content 更新，不需要改 public schema。
- [ ] `V100-015` 建立上游 contract fixture 更新流程，真實 response 必須匿名化後才能進入 repository。

### 3. Migration 與資料保護

- [ ] `V100-020` 建立支援版本的 golden config／DB snapshots，逐一測試升級至 v1.0.0。
- [ ] `V100-021` 每個 migration 在寫入前建立一致性 backup，記錄版本與校驗值。
- [ ] `V100-022` Migration 中斷、磁碟已滿、唯讀、舊 backup 與重跑都具有測試。
- [ ] `V100-023` 提供 UI／CLI 的 backup、restore、integrity check 與 export 操作文件。
- [ ] `V100-024` Installer upgrade、downgrade 拒絕、uninstall 保留資料與「清除所有資料」分別驗收。
- [ ] `V100-025` 定義資料 retention、刪除、credential 清除與 profile 刪除的不可復原警告。

### 4. 安全審查

- [ ] `V100-030` 更新完整 threat model：loopback server、browser boundary、Admin Key、credential stores、SQLite、exports、tray、notifications、updater、CI supply chain。
- [ ] `V100-031` 測試 Host／Origin、DNS rebinding 假設、CSRF、path traversal、header injection、XSS 與本機惡意 process 邊界。
- [ ] `V100-032` 審查 Key 在記憶體、log、exception、crash dump、notification、process args、temp、backup 與 exports 的生命週期。
- [ ] `V100-033` 審查 update signing、key rotation、artifact provenance、CI permissions、第三方 Actions pinning 與 secret exposure。
- [ ] `V100-034` 執行 dependency audit、secret scan、license inventory 與 release SBOM 產生。
- [ ] `V100-035` 所有 critical／high finding 必須修復；例外只能接受有到期日、owner 與緩解措施的中低風險項目。
- [ ] `V100-036` 發布可公開的安全摘要與漏洞回報流程，不公開可直接利用的未修補細節。

### 5. 品質與可靠性

- [ ] `V100-040` Unit、integration、contract、E2E、packaging、migration 與 security tests 分層，失敗可定位。
- [ ] `V100-041` 在三平台執行至少 72 小時 soak test，涵蓋排程、sleep/resume、網路切換與 UTC reset。
- [ ] `V100-042` 使用大型合成資料驗證啟動、30／365 天 query、export、backup 與 migration 效能門檻。
- [ ] `V100-043` 模擬 401、403、429、5xx、timeout、部分頁面、磁碟滿、DB busy／corrupt、credential locked 與 update failure。
- [ ] `V100-044` UI accessibility 檢查鍵盤操作、focus、contrast、screen-reader labels 與 200% scaling。
- [ ] `V100-045` zh-TW／English 的主要 E2E、長字串與 fallback 測試在三平台執行。
- [ ] `V100-046` Release build 可重複產生相同來源對應的版本與 SBOM；不可重現差異需文件化。

## 支援版本升級矩陣

正式 freeze 時填入實際最小支援版本；至少保留以下類型的 golden snapshots：

| 來源版本 | Config migration | DB migration | Credential reference | Alerts／Profiles | 結果 |
|---|---|---|---|---|---|
| v0.2.x | 必測 | 建立／遷移 | 必測 | 建立預設值 | 未執行 |
| v0.3.x | 必測 | 必測 | 必測 | 必測 | 未執行 |
| v0.4.x | 必測 | 必測 | 三平台必測 | 必測 | 未執行 |
| v0.5.x | 必測 | 必測 | 多 profile 必測 | 必測 | 未執行 |

如果某來源版本不支援直接升級，必須在 release 前提供明確的中繼升級或 export／import 路徑。

## 自動化驗證

```text
python scripts/validate_models.py
python -m pytest -q
node --check web/js/app.js
python scripts/validate_locales.py
python scripts/validate_contracts.py
python -m pip_audit
python scripts/generate_sbom.py --output dist/sbom.json
```

`V100-008` 必須建立 `scripts/validate_contracts.py`，`V100-034` 必須把 `pip-audit` 與 SBOM 工具加入開發／發行依賴並建立 `scripts/generate_sbom.py`；這些命令全部加入 CI 後才可進入待驗收。正式 Release workflow 必須從受保護 tag 執行，產出三平台 artifact、checksums、signed manifest 與 SBOM。

## 驗收案例

### `AC-100-01` 支援版本無損升級（P0）

1. 對升級矩陣中的每一個 golden snapshot 建立獨立副本。
2. 升級至 v1.0.0，啟動並執行 integrity check。
3. 比較設定、profiles、projects、usage totals、alerts 與 credential references。

預期：所有支援版本升級成功且數值不變；新增預設值符合文件；失敗 snapshot 可由 backup 復原。

### `AC-100-02` App API Compatibility（P0）

1. 對 `/api/v1` 執行公開契約測試與 golden consumer tests。
2. 注入未知 optional response 欄位及上游欄位順序變化。
3. 觸發所有文件化 error code。

預期：必要欄位與語意符合文件；新增未知欄位不破壞 consumer；error envelope 穩定且不洩漏 exception／Key。

### `AC-100-03` 安全邊界（P0）

1. 執行 security test suite 與人工 review checklist。
2. 搜尋 artifact、config、DB、log、temp、backup、export、crash report 與 process arguments。
3. 驗證 updater tamper／rollback 與 credential revoke。

預期：沒有 critical／high finding；Key 不落地或外洩；被竄改更新不執行；撤銷 credential 後不再背景查詢。

### `AC-100-04` 三平台安裝生命週期（P0）

1. 在支援矩陣每個 OS／arch 執行 install → first run → query → background sync → update → rollback test → uninstall。
2. 驗證簽署、notarization、checksum 與 SBOM。

預期：所有階段符合文件；資料保留／刪除依使用者選擇；無殘留 process、自啟項目或失效 shortcut。

### `AC-100-05` 72 小時 Soak（P0）

1. 三平台各執行 72 小時候選版，使用 fake／sandbox data 定期同步。
2. 期間包含 sleep/resume、網路中斷、UTC reset、429 與程式重啟。

預期：無未受控 memory／handle 增長；無重複 bucket／通知；scheduler 可恢復；DB integrity 通過。

### `AC-100-06` 備份與災難復原（P0）

1. 建立完整 backup。
2. 分別模擬設定損壞、DB migration 中斷、DB corruption 與錯誤新版本。
3. 依公開文件由另一位驗收者操作復原。

預期：驗收者不需閱讀程式碼即可完成復原；歷史資料與設定符合 recovery point；原始故障檔被保留。

### `AC-100-07` 文件可執行性（P0）

1. 讓未參與開發的驗收者只使用公開文件，在三平台完成安裝、首次查詢、profile、匯出、backup、更新與移除。

預期：不需要未文件化步驟；所有命令與畫面名稱正確；中英文文件結果一致。

### `AC-100-08` 效能與 Accessibility（P1）

1. 使用固定大型合成資料執行效能 benchmark。
2. 以鍵盤、screen reader 基本流程與 200% scaling 操作主要 UI。

預期：符合核准的效能 budget；主要流程無鍵盤阻擋；狀態不只依顏色傳達；內容不被裁切至不可使用。

## 回復策略

- 正式發布發現 data-loss、credential exposure、updater compromise 或無法啟動時，立即停止 update manifest 指向該版本並撤下受影響 artifact。
- 不覆寫 tag 或已發布 artifact；修復以 v1.0.1 發布。
- Migration 前 backup 為必要步驟；應用程式自動復原失敗時依公開 runbook 操作。
- 上游 API 變動時優先更新 adapter、fixture 與 catalog content，不破壞 `/api/v1`、config 或 export 契約。
- Signing key incident 依 key rotation runbook 停止簽署、撤銷 key ID 並發布受信任的恢復版本。
