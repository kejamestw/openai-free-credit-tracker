# v0.4.0 執行與驗收計畫

> 規劃聲明：本文件是可調整的規劃草案，不構成功能、日期或上游 OpenAI 規則的承諾；實際發布範圍以對應 Release Milestone 與已完成的驗收紀錄為準。

## 版本資料

- 狀態：跨平台 abstraction／CI 已實作；待三平台原生套件、簽署與 VM 驗收（不可標為已完成）
- 版本主題：macOS 與 Linux 跨平台版
- 前置版本：[v0.3.1](v0.3.1.md)
- 建議工期：單人 15–25 個工作天
- 發布產物：macOS 安裝包、Linux AppImage／tarball、跨平台 CI、平台安全儲存與通知

## 版本目標

在保留 Windows 功能與資料契約的情況下，讓應用程式可在 macOS 與主流 Linux 桌面環境安裝、啟動、查詢、保存歷史、使用 tray、背景同步與通知。所有平台差異必須由 platform abstraction 隔離，核心計算與資料格式不得 fork。

## 現況與證據（2026-08-20）

- `platform_adapters/`、native paths／credentials／startup／tray／notification／instance-lock contracts、三 OS CI matrix 與 package verification tests 已存在。
- [ ] `AC-040-01` 三平台首次啟動；blocker：clean Windows／macOS／Ubuntu VM 與真實 artifact。
- [ ] `AC-040-02` 安全 credential backend；blocker：三平台原生 credential service 與真實測試 Key。
- [ ] `AC-040-03` Linux 無 Secret Service／tray；blocker：實際 DBus／desktop session。
- [ ] `AC-040-04` macOS 簽署與 Gatekeeper；blocker：Developer ID、notarization ticket、clean Mac。
- [x] `AC-040-05` 跨平台資料一致性（平台無關 core fixtures 在 CI matrix 執行）
- [ ] `AC-040-06` 升級與資料保留；blocker：三平台 installer upgrade／uninstall 生命週期。
- [ ] `AC-040-07` 通知、休眠與單一 instance；blocker：原生桌面、sleep/resume、點擊通知。

## 成功結果

同一份核心程式碼能在支援的 Windows、macOS、Linux 環境通過功能與安全驗收；設定與資料寫入各平台標準路徑；Admin API Key 分別使用 Windows Credential Manager、macOS Keychain、Linux Secret Service；缺少桌面服務時安全降級為手動前景模式。

## 支援矩陣

正式發布前在本表填入實際 runner 與機器版本，不以「latest」取代驗收紀錄：

| 平台 | 最低支援目標 | 架構 | 發行格式 |
|---|---|---|---|
| Windows | Windows 10／11 | x86_64 | installer、portable EXE |
| macOS | 發布時仍受 Apple 安全更新支援的兩個主要版本 | arm64、x86_64 或 universal2 | signed／notarized DMG 或 ZIP |
| Linux | Ubuntu 22.04 LTS、24.04 LTS | x86_64 | AppImage、tar.gz |

任何支援矩陣變更都必須在 release candidate 前決定，並同步更新安裝文件。

## 範圍內

- Platform abstraction 與 capability detection。
- macOS、Linux 的 config/data/cache/log 路徑。
- macOS Keychain、Linux Secret Service credential backend。
- macOS、Linux tray、notification、single instance 與 foreground fallback。
- macOS signed/notarized package、Linux AppImage／tarball。
- 跨平台 CI、安裝、升級、資料遷移與 smoke tests。
- 在具備安全簽署條件的平台延伸自動更新；不具備時只提供手動檢查。

## 範圍外

- 多組織與多語言。
- Mobile、WSL、容器或 headless server 的正式支援。
- Linux 全發行版與所有 desktop environment。
- 未簽署 macOS binary 的正式 stable 發布。
- 在缺少安全 credential backend 時以明文保存 Key。

## 執行計畫

### 1. Platform abstraction

- [x] `V040-001` 定義 `PlatformPaths`、`CredentialStore`、`TrayAdapter`、`NotificationAdapter`、`StartupAdapter`、`InstanceLock` 與 `UpdaterAdapter` 介面。
- [x] `V040-002` 將核心計算、OpenAI client、SQLite repository 與 export service 保持平台無關。
- [x] `V040-003` 建立 capability detection；缺少 tray、notifications 或 credential service 時回傳明確狀態。
- [x] `V040-004` 禁止用大量 scattered `if sys.platform`；平台判斷集中在 composition root／adapter factory。
- [ ] `V040-005` 為每個 adapter 建立 contract tests，確保三平台語意一致。

### 2. 路徑與資料遷移

- [x] `V040-010` 使用各平台標準 config、data、cache、log 目錄，所有路徑列入文件。
- [x] `V040-011` 程式從任意工作目錄啟動都不向 cwd 寫入檔案。
- [ ] `V040-012` Windows 現有資料路徑保持相容；若調整路徑，提供一次性可回復 migration。
- [ ] `V040-013` macOS/Linux path 中的 Unicode、空白、唯讀與不足空間都有錯誤處理。
- [ ] `V040-014` SQLite file permissions 採最小存取；backup/export 依使用者選擇路徑處理。

### 3. Credential 與本機安全

- [x] `V040-020` macOS 使用 Keychain backend，支援保存、讀取、刪除、拒絕存取與鎖定狀態。
- [x] `V040-021` Linux 使用 Secret Service backend，辨識 DBus／keyring 不可用狀態。
- [x] `V040-022` 無安全 backend 時停用背景同步，只允許當次記憶體 Key；不得 fallback 到文字檔。
- [ ] `V040-023` 各平台 credential label、service name 與 account ID 不包含完整 Key 或不必要的私人資料。
- [ ] `V040-024` loopback、Host／Origin、path traversal 與 Key 不落地測試在三平台執行。

### 4. Tray、通知與生命週期

- [ ] `V040-030` macOS menu bar、Linux tray 與 Windows tray 提供相同核心操作。
- [x] `V040-031` 不支援 tray 的 Linux desktop 可用 foreground 模式，不崩潰、不背景保存 Key。
- [ ] `V040-032` macOS/Linux single instance、喚醒 Dashboard、sleep/resume 與 clean exit 行為與 Windows 一致。
- [ ] `V040-033` 通知權限被拒絕時 UI 顯示狀態，scheduler 繼續但不反覆要求權限。
- [x] `V040-034` Deep link 或通知點擊輸入必須驗證，不允許任意 URL 或檔案路徑注入。
- [ ] `V040-035` 開機啟動在各平台預設關閉，可啟用、停用並由 uninstall 清理。

## 自動化驗證

所有平台至少執行：

```text
python -m pip install -e .
python -m pip install -r requirements-dev.txt
python scripts/validate_models.py
python -m pytest -q
node --check web/js/app.js
```

打包與簽署命令由各 OS 的 release workflow 執行。正式驗收證據必須包含 workflow run、artifact hash，以及真實乾淨機器或 VM 的 smoke test 結果。

## 驗收案例

### `AC-040-01` 三平台首次啟動（P0）

1. 在支援矩陣每個 OS 的乾淨環境安裝正式候選 artifact。
2. 啟動並打開 Dashboard。
3. 完成匿名 fixture 模式或測試帳號查詢後退出。

預期：資源完整；只監聽 loopback；資料寫入標準目錄；沒有 cwd 污染；退出後無殘留 process。

### `AC-040-02` 安全 credential backend（P0）

1. 在 Windows Credential Manager、macOS Keychain、Linux Secret Service 分別保存測試 Key。
2. 重啟後執行背景同步，再使用 UI 刪除 credential。

預期：背景同步成功；設定、DB、log 無明文 Key；刪除後背景同步停止並要求重新輸入。

### `AC-040-03` Linux 無 Secret Service／tray（P0）

1. 在沒有 DBus Secret Service 或 tray host 的支援 Linux 環境啟動。
2. 嘗試開啟背景監控並完成一次手動查詢。

預期：程式安全降級為 foreground；不保存 Key；不崩潰；UI 說明缺少 capability 及修復方式。

### `AC-040-04` macOS 簽署與 Gatekeeper（P0）

1. 從 Release 下載 macOS artifact。
2. 使用系統工具驗證簽署與 notarization。
3. 以一般使用者正常開啟。

預期：簽章有效、notarization 通過、Gatekeeper 不要求繞過安全機制；應用程式可正常啟動。

### `AC-040-05` 跨平台資料一致性（P0）

1. 在三平台載入相同匿名 Usage fixtures。
2. 比較每日彙總、趨勢 query 與 CSV／JSON exports。

預期：除平台換行等明確文件差異外，token、日期歸屬、project filter 與 JSON schema 完全一致。

### `AC-040-06` 升級與資料保留（P0）

1. 各平台以前一版本建立設定、credential、DB 與警示規則。
2. 升級至 v0.4.0 候選版。

預期：資料 migration 成功；設定與歷史保留；credential 可讀；失敗時可復原且原檔未被破壞。

### `AC-040-07` 通知、休眠與單一 instance（P1）

1. 各平台啟動兩次、進入 sleep/resume、跨越測試門檻並退出。

預期：每平台只有一個 instance；喚醒後只補必要同步；通知不重複；退出無殘留工作。

## 回復策略

- Platform adapter 失敗時降級到 foreground 模式，核心 Usage、history、export 仍可用。
- Credential service 不可用時停止背景同步，不遷移 Key 到檔案。
- 平台 migration 前備份設定與 DB；失敗時保留舊路徑資料並顯示人工恢復方式。
- 某平台 P0 問題不阻止其他平台發 patch，但該平台 artifact 必須撤下或標示 pre-release，不得宣稱正式支援。
