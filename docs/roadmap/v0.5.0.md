# v0.5.0 執行與驗收計畫

> 規劃聲明：本文件是可調整的規劃草案，不構成功能、日期或上游 OpenAI 規則的承諾；實際發布範圍以對應 Release Milestone 與已完成的驗收紀錄為準。

## 版本資料

- 狀態：未開始
- 版本主題：多組織與多語言版
- 前置版本：[v0.4.0](v0.4.0.md)
- 建議工期：單人 12–18 個工作天
- 發布產物：Profile／Organization 資料模型、跨組織切換、zh-TW／English 語系

## 版本目標

讓同一位使用者可以安全管理多個 OpenAI 組織 profile，並在組織與專案之間切換、同步、查看趨勢與匯出；同時建立可延伸的 i18n 架構，正式支援繁體中文與英文。不同 profile 的 credential、資料、警示與同步狀態必須嚴格隔離。

## 成功結果

使用者可以建立兩個以上 profile，每個 profile 綁定自己在作業系統安全儲存中的 Admin API Key；選擇 profile 後，畫面、歷史、專案、警示與匯出只使用該 profile 資料。切換語言後所有主要流程立即套用，缺少翻譯時安全 fallback，不顯示原始 translation key。

## Profile 契約

非敏感設定可保存：

```text
profile_id          本機產生、不重用的 opaque ID
display_name        使用者自訂名稱
organization_ref   遮罩或私有保存的組織識別
credential_ref     指向 OS credential store，不是 Key
enabled             是否允許同步
created_at          UTC
last_validated_at   UTC
```

Admin API Key 只能保存在平台 credential backend。刪除 profile 與刪除歷史資料是不同操作，UI 必須分開確認。

## 執行計畫

### 1. Profile domain 與 migration

- [ ] `V050-001` 建立 profile repository 與 service；UI 不得直接操作 credential 或 DB rows。
- [ ] `V050-002` 為 projects、usage buckets、collection runs、alert rules 與 notification history 加入 `profile_id`。
- [ ] `V050-003` 所有 unique key 與 query 都包含 `profile_id`，避免不同組織相同 Project ID 或 bucket 衝突。
- [ ] `V050-004` 將既有資料原子 migration 到一個 default profile；migration 前建立 config／DB backup。
- [ ] `V050-005` Profile ID 使用本機 opaque identifier，不從 display name、Key 或 Organization ID 推導。
- [ ] `V050-006` Profile 重新命名只改 display name，不改主鍵、credential reference 或歷史關聯。
- [ ] `V050-007` Profile 停用後停止排程與警示，但保留唯讀歷史和匯出能力。

### 2. Credential 與組織驗證

- [ ] `V050-010` 每個 profile 使用獨立 credential item，credential account key 為 profile ID。
- [ ] `V050-011` 新增 profile 時以最小必要 API call 驗證 Key，取得或確認組織身分；失敗不得建立半完成的啟用 profile。
- [ ] `V050-012` 偵測相同 credential 被綁到多個 profile，要求使用者確認或阻擋不明重複。
- [ ] `V050-013` API 回應的組織識別與 profile 預期不符時停止寫入，標記 profile 需要重新驗證。
- [ ] `V050-014` 刪除 credential 後 profile 自動停用；不得改用另一個 profile 的 Key。
- [ ] `V050-015` 切換 profile 時清除記憶體中的前一組 Key 與 request context。
- [ ] `V050-016` Log、notification、diagnostics 預設使用遮罩 profile ID／display name，不輸出 Key。

### 3. Profile UI 與同步

- [ ] `V050-020` 全域 profile selector 顯示目前 profile 與同步狀態；沒有選擇時禁止發 API request。
- [ ] `V050-021` 提供建立、驗證、重新命名、停用、刪除 credential、刪除 profile 的獨立操作。
- [ ] `V050-022` 切換 profile 後 Dashboard、projects、history、alerts 與 last-sync 狀態原子更新，不短暫混顯前一 profile。
- [ ] `V050-023` Scheduler 每個 profile 有獨立 interval／backoff／last run，但全域限制同時 API request 數。
- [ ] `V050-024` 通知必須包含足以辨識的安全 profile label；點擊後開啟正確 profile 與 project。
- [ ] `V050-025` 匯出明確記錄所選 profile；預設遮罩 organization／project identifiers。
- [ ] `V050-026` Profile 刪除前顯示 credential、設定、歷史、alerts 各自處理方式，破壞性刪除需二次確認。

## 自動化驗證

```text
python scripts/validate_models.py
python -m pytest -q
node --check web/js/app.js
python scripts/validate_locales.py
```

`V050-040` 必須建立 `scripts/validate_locales.py` 並加入 CI；在該工作完成前，本版本不可進入待驗收。所有 profile 測試使用假 Key 與匿名 Organization／Project identifiers。

## 驗收案例

### `AC-050-01` 建立兩個組織 Profile（P0）

1. 建立 Profile A、B，各自保存專用測試 Key。
2. 驗證並同步不同匿名組織 fixture。
3. 重啟程式。

預期：兩個 profile 各自驗證；credential 獨立；重啟後顯示正確 last-sync；設定與 DB 無明文 Key。

### `AC-050-02` 跨 Profile 資料隔離（P0）

1. 讓 A、B 使用相同 project ID、model、bucket timestamp，但不同 token 數。
2. 切換 profile，查看 Dashboard、history、alerts 與 export。

預期：每個 view 只顯示所選 profile 數字；DB unique key 不衝突；匯出不混入另一 profile records。

### `AC-050-03` 慢 Request 下切換 Profile（P0）

1. 在 A 開始延遲 API request。
2. 回應前切換到 B 並完成 B 同步。
3. 讓 A request 返回。

預期：A 結果只寫入 A；B 畫面不被 A 回應覆蓋；request context 沒有使用錯誤 credential。

### `AC-050-04` 現有資料 Migration（P0）

1. 使用 v0.4.0 的設定、DB、credential 與 alerts 啟動候選版。
2. 執行 migration 後檢查 default profile。
3. 模擬 migration 中途失敗並重試。

預期：原資料完整歸入 default profile；credential reference 正確；失敗可 rollback；重跑不重複資料。

### `AC-050-05` Credential／組織不符（P0）

1. 將 Profile A 的 credential 替換為 B 的測試 Key。
2. 執行同步。

預期：驗證發現組織不符，停止寫入並停用 A 的背景同步；不把 B 資料寫入 A。

### `AC-050-06` 中英文完整流程（P0）

1. 分別使用 zh-TW、English 完成新增 profile、查詢、趨勢、匯出、警示與刪除 credential。
2. 觸發 validation、401、429、offline 與空資料狀態。

預期：所有主要文字與錯誤正確翻譯；沒有 raw translation key；數字／日期格式符合 locale；資料值不因語言改變。

### `AC-050-07` Translation Fallback（P1）

1. 在測試 locale 移除一個非關鍵 key，並設定不支援的 OS locale。
2. 啟動與切換語言。

預期：缺 key 使用基準語言；不支援 locale 依政策 fallback；UI 不崩潰、不顯示空白。

## 回復策略

- Migration 前備份 DB、config 與 credential references；失敗時不刪除舊單 profile 資料。
- Profile 驗證失敗時停用該 profile 的寫入與背景同步，其他 profile 繼續運作。
- i18n resource 載入失敗時 fallback 至內建基準語言，不阻止核心資料存取。
- 刪除 profile 或歷史是使用者明確破壞性操作，不納入自動 rollback；執行前必須提供 backup/export 選項。
