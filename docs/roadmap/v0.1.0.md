# v0.1.0 執行與驗收計畫

> 本文件是 v0.1.0 的 scope、工作項目、發布門檻與驗收紀錄。工作項目完成不等於版本已發布；未具備人工證據的案例不得標示通過。

## 版本資料

- 狀態：待驗收
- 目標平台：Windows 桌面
- 前置版本：`v0.1.0-alpha.1`
- 開發分支：`feat/v0.1.0-windows-core`
- 預計時程：2026 年第 4 季
- 預期產物：Windows portable EXE、`SHA256SUMS.txt`、Changelog

## 版本目標

將 alpha 原型整理成第一個可驗收的 Windows 核心版本：使用者在乾淨 Windows 電腦執行單一 EXE，瀏覽器開啟本機 UI，輸入 Organization Owner Admin API Key 後，可以查看當日 UTC 用量、已確認的 incentivized／data-sharing 免費群組、其他用量、目錄價格估算及 Costs API 實際費用。Key 不得持久化。

## 使用者故事

身為不想安裝 Python、clone repository 或把 Admin Key 交給第三方服務的 Windows 使用者，我希望下載 portable EXE，在只監聽 loopback 的本機服務中查詢資料，並能明確辨認免費用量、其他用量、估算與實際費用。

## 自動驗證命令

```powershell
python -m pip install -e .
python -m pip install -r requirements-dev.txt
python scripts\validate_models.py
python scripts\audit_repository.py
python -m pytest -q
node --check web\js\domain.js
node --check web\js\app.js
node --test tests\frontend_domain.test.cjs
git diff --check
```

Windows build 與本機 artifact 驗證：

```powershell
scripts\build_windows.bat
dist\OpenAI-Free-Credit-Tracker.exe --version
dist\OpenAI-Free-Credit-Tracker.exe --smoke-test
Get-FileHash dist\OpenAI-Free-Credit-Tracker.exe -Algorithm SHA256
```

預期：所有命令 exit code 為 0；`dist/` 內 one-file EXE 可在沒有系統 Python 的乾淨 Windows VM 啟動。最後一項仍需人工 VM 驗收，不能由開發機 build 取代。

## 驗收案例

### `AC-010-01` 乾淨 Windows 首次使用（P0）

1. 準備沒有 Python 的乾淨 Windows 10 與 Windows 11 VM。
2. 從正式 Release 下載 EXE 與 checksum。
3. 驗證 SHA-256 後啟動 EXE。
4. 確認瀏覽器只開啟 `http://127.0.0.1:<random-port>`，首頁、CSS、JavaScript 與模型目錄均載入，未輸入 Key 前不送 OpenAI request。

預期：標準使用者權限即可啟動，不依賴 Python，不缺 bundled resource，不寫入 Key。

### `AC-010-02` 真實 Admin Key 查詢（P0）

1. 輸入專用且可撤銷的 Organization Owner Admin API Key。
2. 更新當日資料。
3. 與 OpenAI organization Usage／Costs 或帳務後台抽樣比對。

預期：所有分頁都納入；只有已確認 incentive tier 加入免費群組；其他用量、未知模型、目錄估算與 Costs 實際費用分開；UI 與 log 不顯示完整 Key。驗收後立即撤銷測試 Key。

### `AC-010-03` 無效 Key 與 API／網路錯誤（P0）

1. 依序測試空值、錯誤 prefix、短 Key、已撤銷 Key、權限不足、429、OpenAI 5xx、timeout、離線及不支援 response。
2. 觀察 UI、local server log 與 browser Network response。

預期：錯誤可讀且可重試；response 只有安全 envelope 與 request ID；無 Key、Authorization header、上游 body 或 traceback；Costs-only 失敗呈現部分成功。

### `AC-010-04` Key 不落地（P0）

1. 執行一次成功與一次失敗查詢後關閉程式。
2. 檢查 application directory、browser localStorage／sessionStorage／IndexedDB／cookies、server log、Windows Recent 與一般 crash/diagnostic 位置。
3. 重啟程式。

預期：找不到完整 Admin Key；重啟後輸入框為空且必須重新輸入。

### `AC-010-05` Loopback 與路徑邊界（P0）

1. 取得 UI 顯示的 port，執行 `Get-NetTCPConnection -LocalPort <port>`。
2. 確認 `LocalAddress` 只有 `127.0.0.1`，沒有 `0.0.0.0`、`::` 或 LAN address。
3. 從同 LAN 的另一台電腦連到 `<Windows-LAN-IP>:<port>`，應連線失敗。
4. 請求 `/../data/models.json`、`/%2e%2e/data/models.json`、backslash 與 NUL traversal。

預期：只有 loopback listener；跨機無法連線；traversal 回 403 或 404 且不洩漏檔案或本機路徑。

### `AC-010-06` 關閉與重啟（P1）

1. 關閉 EXE console window 或按 `Ctrl+C`。
2. 確認原 port 不再 listen，沒有殘留 tracker process。
3. 連續重新啟動、查詢、關閉三次。

預期：每次只有一組 process／server；舊 port 釋放；新 session 不保留 Key 或前次查詢資料。

## 待人工驗收操作清單

1. 從尚未安裝 Python 的 Windows 10、Windows 11 VM snapshot 各執行 `AC-010-01`。
2. 只在受控 VM 產生或使用可立即撤銷的專用 Admin Key，執行 `AC-010-02`～`04`，結束後撤銷。
3. 準備同 LAN 第二台電腦，依 `AC-010-05` 檢查 listener 與跨機連線。
4. 依 `AC-010-06` 重複三次 lifecycle，記錄 PID、port、關閉後的 `Get-NetTCPConnection` 與 Process 證據。
5. 對每個案例記錄日期、Windows build、EXE SHA-256、測試者、結果、截圖／log 路徑；證據不得包含 Key 或未匿名化 response。

## 回滾原則

- 本次變更只存在 local feature branch。未合併前的安全回滾方式是保留此分支並 `git switch main`；不得 reset、rebase、force-push 或刪除既有 tag。
