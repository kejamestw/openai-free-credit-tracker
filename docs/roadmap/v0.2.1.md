## 版本目標

在不降低本機工具安全性的前提下，提供可選擇的 Windows 自動更新。程式只能安裝由專案發布流程簽署且 hash 相符的更新；下載中斷、檔案遭竄改或新版本無法啟動時，現有版本仍必須可用。

## Update manifest 契約

建議 manifest 每個平台項目至少包含：

```json
{
  "schema_version": 1,
  "channel": "stable",
  "version": "0.2.1",
  "published_at": "2026-01-01T00:00:00Z",
  "minimum_updater_version": "0.2.0",
  "artifact": {
    "url": "https://example.invalid/release.exe",
    "size": 123,
    "sha256": "hex-value"
  },
  "release_notes_url": "https://example.invalid/release",
  "signature": "base64-value",
  "key_id": "release-key-1"
}
```

簽章必須涵蓋 canonicalized manifest 的所有非簽章欄位。URL、version、channel、size 與 hash 不得置於簽章範圍外。

## 自動化驗證

```powershell
python -m pytest -q
python scripts\validate_models.py
node --check web\js\app.js
```

更新器測試需使用 repository 內的測試 signing key；正式 private key 只能存在於受保護的 Release job，且非 tag CI 不得取得。

## 驗收案例

### `AC-021-01` 正常 stable 更新（P0）

1. 在 VM 安裝前一個 stable 版本並建立非敏感設定。
2. 提供合法、已簽署的新 stable manifest。
3. 同意下載與安裝。

預期：簽章、size、hash 驗證通過；新版本啟動並通過健康檢查；原設定保留；舊 artifact 可依政策清理。

### `AC-021-02` Manifest 遭竄改（P0）

1. 分別修改已簽署 manifest 的 URL、版本、hash 與 channel。
2. 執行更新檢查。

預期：所有修改都因簽章失敗而被拒絕；不下載 artifact；UI 顯示安全錯誤；現有版本繼續運作。

### `AC-021-03` Artifact 遭竄改（P0）

1. 使用合法 manifest，但讓下載內容少一個 byte 或替換內容。
2. 執行更新。

預期：size 或 SHA-256 驗證失敗；檔案不被執行；暫存檔安全清理；現有版本不變。

### `AC-021-04` 更新中斷與 rollback（P0）

1. 在下載、替換、首次啟動健康檢查三個階段分別強制終止 process。
2. 重新啟動應用程式。

預期：每個階段都能恢復舊版或繼續已驗證流程；不存在同時不可用的新舊版本；設定未損壞。

### `AC-021-05` Channel 與降版（P0）

1. stable 使用者收到 beta manifest。
2. beta 使用者收到較新 beta。
3. 任一使用者收到低於目前版本的合法 manifest。

預期：stable 忽略 beta；beta 正常提示；降版被拒絕並記錄原因。

### `AC-021-06` 離線與拒絕更新（P1）

1. 在離線環境啟動。
2. 恢復網路後檢查更新，但選擇稍後或略過版本。

預期：離線不影響主要功能；使用者選擇被記錄；程式不重複打擾且可手動重新檢查。

### `AC-021-07` 正式 signing key 隔離（P0）

1. 檢查一般 CI、PR job、build artifact、log 與 repository history。
2. 嘗試從非 tag workflow 取得正式簽署能力。

預期：找不到 private key；非授權 job 無法簽署正式 manifest；只有受保護的 Release job 可使用。

## 回復策略

- 新版本健康檢查失敗時，自動恢復最近可用 binary 或交回 installer rollback。
- 已下載但未完成驗證的檔案永遠不得執行。
- Manifest 或簽署服務故障時，停止更新提示，不影響既有版本。
- Signing key 疑似洩漏時，停止發布 manifest、撤銷對應 key ID，透過已信任 key 發布輪替版本。

## 完成定義

只有在簽署、下載、驗證、安裝、健康檢查與 rollback 全流程都以舊版對新版完成驗收，所有安全門檻具有證據，且使用者可安全停用更新時，才能將本文件狀態改為「已完成」。
